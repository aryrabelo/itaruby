# Corpus baseline — the sacred numbers, in machine-readable form.
#
# WHY HASHES, NOT TEXT: an `err` line from `ita check` contains a client's
# file path (and sometimes a client class/method name). This file is public
# git history (see AGENTS.md — the repository is public). So no
# error line is ever written here in the clear: each declared corpus lists
# the SHA-256 (first 16 hex chars) of its expected error lines, normalized
# by stripping the corpus's mapped path (see scripts/corpora-local.txt,
# gitignored, one machine-local `<id> <path>` line per corpus) from the
# front of each `ita check` output line and replacing it with `<id>/` before
# hashing — one trailing newline included, i.e.:
#
#   printf '%s\n' "$line" | shasum -a 256 | cut -c1-16
#
# where $line already had its corpus root replaced by `<id>/`. This keeps
# the hash independent of both the machine (no absolute mount point survives
# it) and the corpus's own directory layout (no client repo name or nesting
# survives it either) — a corpus can move, get renamed, or nest one level
# deeper on its host without moving a single hash in this file. The gate
# recomputes hashes from a fresh run and compares the SET, never the text.
# When a run drifts, the gate writes the actual in-clear lines to
# `target/gauntlet/corpus-<id>-drift.txt` — gitignored, stays on the machine
# that has the corpus — and the transcript only prints counts (how many new,
# how many gone) plus that filename.
#
# `warn_ceiling` is a ceiling, not an equality: warnings are the
# external-declaration gap (bead ita-10d), so they may fall freely and must
# never rise. A rise is either OUR regression (revert it) or corpus drift
# (these are living client repos) — and the second case is only ever settled
# by measurement, never by assumption. The `measured` comment on each corpus
# records the .rb file count its ceiling was taken against, so the next
# drift is attributable in one step instead of a git-archive bisect (bead
# ita-vbj: a stale-checkout ceiling once read as a false regression for a
# day).
#
# The `corpus_rev` comment on each corpus carries the same duty for the
# revision: the corpus HEAD its ceiling and hashes were measured against. A
# bare git sha identifies no client, and without it a red gate d cannot
# distinguish our detection changing from the client repo moving — which is
# exactly the day that got burned on 2026-09-18 (see AGENTS.md's Rules of
# proof). Every ratchet updates it in the same commit as the number.
#
# Corpus ids are generic (corpus-a, corpus-b, corpus-c) on purpose: their
# real paths are client-identifying and live only in the gitignored,
# machine-local scripts/corpora-local.txt — never in this file, never in git
# history. A corpus is checked only on a machine whose
# scripts/corpora-local.txt maps its id to an existing directory; absent
# corpora (missing mapping file, or no line for that id) are skipped
# individually, by id — see AGENTS.md's Gates table for why full proof needs
# two machines (m5 + work).
#
# Format: one `corpus <id> warn_ceiling=<n>` line declares a corpus,
# followed by zero or more `err <id> <hash>` lines (its expected error-hash
# set). A corpus with zero expected errors (corpus-b) has no `err` lines at
# all.
#
# The hashes on record were regenerated 2026-08-25 under the `<id>/`
# normalization (corpus-a: 2 errors, corpus-b: 0, corpus-c: 3 — same sets
# as the previous path-based hashes, re-derived from clean `ita check`
# runs on the machines holding each corpus).
